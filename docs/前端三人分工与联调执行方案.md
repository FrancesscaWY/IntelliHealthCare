# 前端三人分工与联调执行方案

更新时间：`2026-04-23`

适用范围：

- `apps/user-web`
- `apps/admin-web`
- 后端联调基线：`http://server.mctown.online:8190/api/v1`

本版是替换后的新执行文档，重点解决 4 件事：

1. 用户端和后台端登录必须走真实 API。
2. `APP_TOKEN` 和 `ADMIN_TOKEN` 必须分开存，不允许复用一个 key。
3. 前端所有受保护接口统一从各自的 session 层取 token。
4. 三人并行开发时，登录、token、联调顺序使用同一套口径。

---

## 1. 当前登录与 token 方案

### 1.1 用户端

- 登录接口：`POST /app/auth/login/password`
- 验证码登录：`POST /app/auth/login/sms`
- 第三方登录：`POST /app/auth/login/third-party`
- 当前用户：`GET /app/users/me`
- 退出登录：`POST /app/auth/logout`

落地位置：

- token 存储：`apps/user-web/src/shared/auth/session.ts`
- 请求封装：`apps/user-web/src/shared/api/client.ts`
- 认证接口：`apps/user-web/src/shared/api/auth.ts`

存储规则：

- 用户端 token 固定存到 `localStorage`
- key：`ihc:user-web:auth-session`
- 最后一次登录手机号：`ihc:user-web:last-login-phone`

结论：

- `user-web` 只能读取 `ihc:user-web:auth-session`
- 不能读取后台端 token
- 不能把后台 token 写进用户端存储

### 1.2 后台端

- 登录接口：`POST /admin/auth/login/password`
- 当前后台用户：`GET /admin/auth/me`
- 后台首页：`GET /admin/dashboard/overview`

落地位置：

- token 存储：`apps/admin-web/src/shared/auth/session.ts`
- 请求封装：`apps/admin-web/src/shared/api/client.ts`
- 认证接口：`apps/admin-web/src/shared/api/auth.ts`
- 工作台接口：`apps/admin-web/src/shared/api/workbench.ts`

存储规则：

- 勾选“记住当前登录信息”时，token 存到 `localStorage`
- 未勾选时，token 只存到 `sessionStorage`
- key 统一为 `ihc:admin-web:auth-session`

结论：

- `admin-web` 只能读取 `ihc:admin-web:auth-session`
- 后台 token 绝不能落到 `user-web` 的 key
- 用户 token 绝不能落到后台端的 key

### 1.3 两端公共规则

- 请求头统一写法：`Authorization: Bearer <accessToken>`
- 前端页面禁止手写 token 常量
- 前端页面禁止直接从页面组件里拼装鉴权逻辑
- 必须通过各端自己的 `shared/auth/session.ts` 读取 token
- 必须通过各端自己的 `shared/api/client.ts` 自动加头

## 2. 前端对接 API 时使用 token 的方法

### 2.1 用户端用法

```ts
import { request } from "@/shared/api/client";

const data = await request("/app/users/me", {
  auth: true
});
```

说明：

- `auth: true` 时，`apps/user-web/src/shared/api/client.ts` 会自动从 `ihc:user-web:auth-session` 读取 `accessToken`
- 自动追加请求头：`Authorization: Bearer ${accessToken}`
- 如果返回 `401` 或 `403`，会清空用户端本地 session

### 2.2 后台端用法

```ts
import { request } from "@/shared/api/client";

const data = await request("/admin/dashboard/overview", {
  auth: true
});
```

说明：

- `auth: true` 时，`apps/admin-web/src/shared/api/client.ts` 会自动从后台专用 session 读取 `accessToken`
- 不会读取用户端 session
- 如果返回 `401` 或 `403`，会清空后台端本地 session

### 2.3 禁止做法

- 不要在页面里写 `localStorage.getItem("token")`
- 不要把 `APP_TOKEN` 和 `ADMIN_TOKEN` 共用同一个 key
- 不要把登录返回的整个响应直接散落到多个页面各自保存
- 不要在每个 API 方法里重复手写 `Authorization`
- 不要拿用户端 token 请求 `/admin/*`
- 不要拿后台端 token 请求 `/app/*`

## 4. 联调顺序

用户端标准顺序：

1. `POST /app/auth/login/password`
2. 保存 `data.accessToken` 到 `ihc:user-web:auth-session`
3. `GET /app/users/me`
4. 未实名则去 `auth/real-name`
5. 已实名则去 `home/dashboard`

后台端标准顺序：

1. `POST /admin/auth/login/password`
2. 保存 `data.accessToken` 到 `ihc:admin-web:auth-session`
3. `GET /admin/auth/me`
4. `GET /admin/dashboard/overview`

---

## 5. 提交前自检

每次提测前必须确认：

1. 用户端登录后，`localStorage` 中存在 `ihc:user-web:auth-session`。
2. 后台端登录后，只在后台专用存储位存在 `ihc:admin-web:auth-session`。
3. 用户端请求 `/app/*` 时能自动带 `Authorization`。
4. 后台端请求 `/admin/*` 时能自动带 `Authorization`。
5. 退出登录或 token 失效后，本地 session 会被清空。
6. 页面代码中没有再出现裸写的 `localStorage.getItem("token")`。

---

## 6. 后续扩展要求

- 新增用户端受保护接口时，只在 `apps/user-web/src/shared/api/*` 增加方法
- 新增后台端受保护接口时，只在 `apps/admin-web/src/shared/api/*` 增加方法
- 页面组件只负责调用方法、处理加载态和展示态
- token 读取、鉴权头拼装、401/403 清理逻辑，禁止回到页面组件里重复实现
